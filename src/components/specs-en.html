Overview

Robot Karol is a single-file HTML game for kids. The player builds a program from visual blocks; a robot (Karol) runs it on a tile map: it walks, pushes crates, picks up keys, unlocks doors and must reach the exit. Target: a standalone project later (map editor planned).

Layout

  • Left: block library (collapsible Blocks and Custom blocks), the program panel (or custom-block editor), speed buttons and Run/Step/Stop/Reset/Clear.
  • Right: top bar with inventory and the Levels and Specs buttons, the live canvas map, and a status bar under the map.
  • On narrow screens the layout stacks vertically.

Map

  • Maps are arrays of text rows, any size (default level is 15x15), drawn on a canvas scaled to fit. Short rows are padded with spaces.
  • Symbols: W/w wall, space floor, K Karol start (facing east), k key, b crate, D/d open door, L locked door, e exit.
  • Rooms are detected by flood fill (walls and doors separate rooms) and each room gets its own floor colours. Locked doors show a lock, the exit a flag.

Robot rules

  • Karol moves one cell per Move forward and turns 90 degrees counter-clockwise per Turn left; movement and rotation are animated.
  • Walls and locked doors block (error, program stops). Open doors are passable.
  • Walking into a crate pushes it one cell if the cell behind is free floor or door (no wall, locked door, key, exit or other crate); otherwise error "crate is stuck".
  • Stepping on a key picks it up into the first free inventory slot (if full, the key stays and a message is shown).
  • Reaching the exit wins: after a short pause a "Good job" dialog offers Next level (loads the next level with an empty program; hidden on the last level), Stay (resets the robot, keeps the program for editing) and Restart (resets the robot and clears the program). Closing the dialog leaves everything as is.

Inventory

8 slots shown as an array above the map, numbered 1-8. Items fill the first free index. Use item N applies slot N to the cell directly in front of Karol. A key used on a locked door opens it (door becomes passable) and the key is consumed. Empty slot or no valid target = non-fatal error.

Blocks

  • Turn left, Move forward, Use item [N] (N 1-8), Repeat [N] times (N 1-99, holds nested blocks, can be nested), If, Repeat while and Not (see Sensors; they can also be nested and used in custom blocks).
  • Program runs top to bottom between START and END.
  • Drag from the library into the program; the drop position is previewed live with a dashed placeholder and neighbours shift (live sorting, also inside Repeat). Drag existing blocks to reorder; while dragging, a semi-transparent remove area covers the map: drop a block there to delete it (dropping a block anywhere else outside the program returns it to where it was). The program list has extra space under END so the last position is easy to hit. A block that was just added or moved glows and fades back to normal over 2 seconds. Short sounds play when a block is added, moved or deleted. Works with mouse and touch (pointer events).

Sensors and conditions

  • The expandable Sensors section (above Blocks) holds sensor blocks, which are yes/no questions about the world. Sensor Can go forward is true when Move forward would succeed: the cell ahead is not a wall or locked door, and a crate there could be pushed.
  • If [sensor] runs the blocks inside only when the sensor is true (no else branch). Repeat while [condition] repeats its blocks as long as the condition is true (checked before each round), e.g. Repeat while Can go forward: Move forward walks up to the wall. Not ( [condition] ) (in the Blocks section) is an operator that turns true into false and vice versa. It fits any condition slot and has a slot of its own, e.g. Repeat while Not(Can go forward): Turn left turns until the way is free. Not blocks can be nested.
  • Drag a sensor into the ? condition slot of If / Repeat while / Not (slots are highlighted while dragging; dropping a new sensor replaces the old one; a sensor can be dragged out to the remove area). An empty slot is an error (red dot).
  • Each condition check is its own execution step: the If / Repeat while block lights up and the status bar shows "Can go forward? yes/no". Loops whose body changes nothing stop with an error instead of running forever.

Custom blocks

  • Create opens the editor view (map faded, run controls disabled): name field, block list, Save and Cancel.
  • A custom block is a function that can contain any blocks including other custom blocks. Cycles are prevented (a block cannot contain itself or a block that contains it); execution depth is capped at 20.
  • Library rows have edit and delete (delete asks "Sure?" and removes all usages). Renaming updates existing usages. An empty name gets "Block N".
  • Select mode in the program header: click adjacent blocks of one list to select them, then Make block opens the editor prefilled; Save replaces the selection with the new custom block, Cancel leaves the program unchanged.
  • Custom blocks live in memory only (not persisted yet).

Execution

  • Run (F5) executes with a timer and turns into Pause (F5) while the program is running; Run again continues from where it paused, Step (F6) executes one instruction (continue with Run any time), Stop (Esc; if a dialog is open Esc closes the dialog instead) ends, Reset returns the level to its start, Clear empties the program.
  • Speed: 1x, 3x, 5x, 15x (base 450 ms per instruction); also affects animation.
  • Execution pointer: while running or stepping, a red arrow ▶ in front of the row and a yellow outline mark the block being executed right now (inside loops it jumps back each round). A Repeat N times block is a step of its own at the start of every round (and once more when the loop ends): the arrow points at it, and its badge ⏳ next to the original N counts down the rounds left (N, N-1, ... 0) with a small pop animation. The badge, like the dots, stays until the next run or program change. Loops inside custom blocks have no badge or extra steps.
  • Sonar: whenever a sensor is evaluated, Karol sends a short sonar animation in his facing direction: a fan-shaped beam with expanding arcs, ending in a ping ring on the cell ahead, green when the sensor sees a free cell and red when it is blocked (its length follows the speed setting and it always ends before the next block executes; in single-step mode it plays a bit longer).
  • Safety limits: 5000 execution steps per run and 200000 loop rounds, then the run stops with a message.
  • Status dots: the running block is green; every executed block keeps a green dot, failed or non-executable blocks get a red dot (red wins). Dots clear on the next run or any program change. A custom block call is marked as a whole.

Levels

  • The Levels button lists levels; click one to load it. The current level is restored on reload.
  • Built-in levels: Level 1 (straight walk), Level 2 (spiral corridor), Level 3 (door, key and locked door), Level 4 (a wall of crates to push), Level 5 (key, crate and locked door), Level 6 (long spiral maze), Level 7 (diagonal staircase corridor). Built-in levels are versioned (karol.ver = 5): on first load of this version they replace stored levels with the same id, and other stored levels are kept after them.
  • Level format: {"id":"level-1","name":"...","map":["WWW","W K", ...]}.
  • Stored in localStorage keys karol.levels and karol.level (guarded with try/catch; falls back to memory).
  • Console API: exportLevels() (also exposed on the parent/top window when allowed; in a sandboxed iframe select the iframe in the DevTools console context dropdown) prints the levels JSON and returns the array; importLevels(levels) accepts an array or JSON string, validates (each needs a map with exactly one K), merges by id (same id replaced, new appended) and saves. Returns the number imported.

Options and language

The Options button (after Specs) opens a menu with the language switch: English or Slovak (Slovenčina). It translates the whole interface (labels, blocks, messages); the specs themselves stay English only. The choice is stored in localStorage key karol.lang; the default follows the browser language. User-entered names (custom blocks, levels) are not translated.

Options also has a Sound on/off switch (localStorage key karol.sound).

Technical notes

  • Delivered as one HTML file with no external dependencies, produced by a build from Vue components, Pinia stores and plain logic modules; levels and translations are JSON files combined by the build. Blocks are rendered from the program held in a store, the map is drawn on a canvas. The program is a tree interpreted lazily by a generator, one action or condition check per tick, so sensors always see the live robot state.
  • Planned: map editor, persistence of custom blocks.
